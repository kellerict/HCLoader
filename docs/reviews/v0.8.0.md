# Review v0.8.0 – DJ pages, playlist export (M3U8)

Range: `git diff ef7fccd..HEAD`. I only spot-checked the translation catalogs.
Reviewer: independent `reviewer` agent; no code was changed.
Local run: `pytest tests/test_artists_playlists.py tests/test_api.py tests/test_djs_ui.py`, the i18n/parity tests
and `ruff check .` all pass. I also ran a synthetic benchmark of `artists.build_index` with 2,000 and 10,000 sets
(see m1).

## Verdict: **ÄNDERUNGEN NÖTIG**

No Blocker. There are two Majors. Both are about the credit derivation, the heart of the DJ pages: a
known-artist edit cannot fix a mangled name (M1), and the index cache ignores festival assignments (M2). Neither
touches YouTube, the file system outside the chosen folder, or the migrations. The playlist export is in good shape.

## Checked and in order

- **YouTube/Throttle:** v0.8.0 opens no new network path. `get_artist_watch` (`app/api.py:2257`) and
  `artists.watch_proposal` (`app/core/artists.py:826`) only read the DB. `discover.soundcloud_channel_page` is a DB
  query. Nothing is saved until the user confirms the modal (`ui/js/views/djs.js:219-226`), and then the UI calls the
  existing `save_source` with `auto_download: false`. «Search in Discover» only fills in the search field
  (`discover.js prefill`) and does not search, so no quota is used. `yt_dlp` is still only in `ytclient.py`.
- **Path safety of the export target:** `folder` from the dialog, the config or `pick_folder` must be absolute
  (`playlists.py:320`). The name goes through `paths.sanitize_filename`, which replaces `\ / : |`, handles
  `CON`/`COMn`/`LPTn`/`CONIN$` (`_CON`), strips trailing dots and spaces and removes control characters. Path
  traversal out of the chosen folder is therefore impossible, and only `<name>.m3u8` (plus `.tmp`) is written. The
  length is checked in UTF-16 units against `storage.max_path_length`.
- **Relative paths:** `ntpath.relpath` raises `ValueError` for another drive or a different UNC share, and the code
  then falls back to an absolute path and counts it (`playlists.py:195-206`). It is tested with `ntpath` on Linux.
- **M3U injection:** `label()` collapses `\r\n` (`playlists.py:226`), so a title cannot open its own `#EXTINF` or
  path line. (Edge cases are in m4.)
- **Overwrite:** `exists` → the dialog asks itself → a second request with `overwrite: true`. The write is atomic
  (`tmp` + `os.replace`). Export, preview, sync and every artist edit run serialised on `hcloader-playlists`, so a
  GUI export and a GUI sync cannot race. The SQL is parameterised; the f-string parts are constants.
- **Migration 13:** append-only. It creates two tables with `UNIQUE(key)` / `UNIQUE(path)` and does not touch
  existing tables.
- **Merge/split integrity, basics:** merge deletes the source rows and adds their names and spellings as aliases of
  the target in one transaction. Re-detection resolves those spellings to the target through `_Known`, so a rebuild
  does not undo the merge. The seed list is inserted once (`state.artists_seed_version`), so deleted or merged seed
  artists do not come back. A playlist with `kind: artist` whose key was merged resolves through `resolve_key` to
  the target.
- **b2b:** every artist of a split credit gets the set with role `b2b`. Two spellings that fold to one artist go back
  to `solo` (`artists.py:462`). Known acts that contain a joiner (D-Block & S-te-Fan) stay one act.
- **XSS:** I checked every new `innerHTML` and `insertAdjacentHTML` in `djs.js`, `playlist.js`, `library.js`,
  `collector.js`, `settings.js` (`playlists` custom) and `player.js` (queue). Names, aliases, keys, paths and
  titles all go through `esc()`. `ui.confirm` and `ui.toast` escape their text. The queue label is set with
  `textContent`/`title`. Routing uses `encodeURIComponent`/`decodeURIComponent` and a restrictive hash regex.
- **Player «Play all»:** only sets whose file exists. A set chosen by hand ends the queue. The sleep timer
  (`end`) takes precedence over the next set. `close()` clears the queue.
- **Playwright tests:** they wait explicitly everywhere (`wait_for_selector`, `wait_for_function`,
  `state="detached"`), with no fixed `wait_for_timeout`. Reads after a click only happen once a wait condition has
  been met.
- **Module boundaries:** `core/artists.py` and `core/playlists.py` have no UI imports, and `api.py` delegates to
  them. `get_artist`/`get_artist_watch` assemble the result in a few lines, but they hold no business logic beyond
  the existing source lookup. This is acceptable.
- **Configurability:** `playlists.folder`, `relative_paths` and `sync_after_download` are in `Settings` and
  `config.example.yaml`, and the GUI exposes them (Storage tab, with Browse and the list of saved playlists).
- **i18n:** the new keys exist in `en`/`de`, and the parity tests are green. I spot-checked `de` (pl.*, djs.*):
  it uses ss, not ß.

## Major

### M1 – `_FEAT` strips real names, and a manual artist entry cannot fix it
`app/core/artists.py:60` and `:103-109`, `:139-141`. `_FEAT` matches `with`, `presents` and `pres.` and cuts off
everything after them. `split_credit` runs `_clean_name` **before** the `known.resolve` check:

```
split_credit("Mark With a K")                 -> ['Mark']     (also with "Mark With a K" in the artists table)
split_credit("Mark With a K & MC Chucky")     -> ['Mark']
```

Scenario: Mark With a K is a well-known hardstyle DJ. All of his sets end up under a derived artist «Mark». The user
creates «Mark With a K» as an artist, and nothing changes, because the lookup only sees the already shortened
«Mark». Making «Mark» an alias of him only works around the problem, and it also claims every other «Mark …».
This breaks the promise that manual edits win.
Fix: in `split_credit`, check `known.resolve` on the **raw** text and on every raw piece (after brackets and
`_TAIL`) before `_FEAT` stripping. Only treat `with` as a feature marker when an MC or a further credit follows,
e.g. `\s+(?:feat\.?|ft\.?|featuring|w/)\s+` plus `\s+with\s+MC\b`. Add a test with «Mark With a K».

### M2 – The index cache ignores festival assignments and other edits to the set rows
`app/core/artists.py:335-348`. The signature covers the number of done sets, `MAX(downloaded_at)`, `artists`,
`checklist_rows` and `series`. It does not cover `videos.edition_id`, `stage`, `set_type`, `title` or
`channel_name`, and it does not cover `editions`. Attribution depends directly on these fields: `title_names`
trusts a title only with `edition_id` (`:400`), `channel_names` excludes edition sets (`:415`), and the festival
counter in `_summary` reads `idx.rows`.
Scenario: the user assigns sets to Defqon.1 2024 in the library or runs the «assign festivals» pass
(`series.py:383/555`). The DJ list and DJ pages keep the old credits and festival counts until the next download or
an app restart. The reverse also happens: removing an assignment (`series.py:501/793`) leaves a channel credit
missing.
Fix: add `MAX(rowid)` plus a cheap aggregate over the relevant columns to the signature, for example
`SUM(IFNULL(edition_id,0))`, `COUNT(stage)` and `MAX(editions.rowid)`. Alternatively, call `artists.invalidate(db)`
in `series.assign/unassign` and in every other write path that changes title or channel.

## Minor

- **m1 – Index build cost on large libraries** (`artists.py:422-466`, hotspot `festivals.contains` → `norm()`).
  The benchmark took about 1.1 s for 2,000 sets and about 5.2 s for 10,000 sets (Linux; Windows is usually slower).
  About 75 % of that time is `fx.norm`, which runs again for every alias in every `contains` call (`festivals.py:238`),
  on aliases that are already normalised. The index is rebuilt after every download (the signature changes) and
  after every edit, merge, split or hide. On `done`, the open DJ list reloads too (`djs.js:348`). With
  `sync_after_download`, the playlist sync also blocks the playlist thread for that long. UI calls wait for it
  (`JOB_TIMEOUT_S`), so nothing breaks, but it is noticeable. Fix: precompile the aliases once per catalog, either
  as a single alternation regex or by caching the `norm` result (`lru_cache` on `norm`, or pre-normalised forms in
  `cat.compiled()`). Build `stage_names` once per build and not per title (`artists.py:185`).
- **m2 – Relative entry starting with `#`** (`playlists.py:251`). If the playlist sits in the same folder as the
  set folders (for example, the user picks the music folder itself) and a folder or file name starts with `#`
  (channel «#HardstyleMixes»), the path line reads as a comment, and players skip the entry silently.
  Fix: write `.\` (or `./`) in front of a relative path that starts with `#`.
- **m3 – Sync recreates deleted playlists** (`playlists.py:347-351`, `sync_all`). `_write` calls
  `mkdir(parents=True)` and writes even when the user has deleted the file or its folder in Explorer. Settings shows
  «gone», but after the next download the file is back. Fix: in `sync_all`, skip a missing file (or a missing parent
  folder) and count and report it as `gone`. Alternatively, set `sync = 0` automatically.
- **m4 – EXTINF fallback without line sanitising** (`playlists.py:250`). The fallback
  `labels.get(...) or r.get('title') or r['id']` writes the raw title when `label()` returns an empty string. Example:
  a title made only of whitespace or line breaks and an empty channel. This is practically unreachable, but cheap to
  fix: apply `_LINE.sub` in `render`, and also to `p` (on non-Windows systems a file name can contain `\n`). U+2028
  and U+0085 can also break lines for some parsers.
- **m5 – Lost sync request (race)** (`api.py:2335-2347`). `_playlist_sync_job` checks `_pl_dirty` and leaves the
  loop. If a download finishes before `Worker._release`, then `submit("pl-sync")` returns the old, still pending
  future (`worker.py:272`), and the request is lost. The last download of a batch then does not show up in the
  playlists until the next download. Fix: check `_pl_dirty` again after the job (in a `finally` that resubmits), or
  give the sync job a fresh key per request and let the dirty flag deduplicate.
- **m6 – Alias limit inconsistent after merge** (`artists.py:780` vs `:650`). Merge stores up to 80 aliases and
  silently drops the rest. Those spellings come back as separate artists, so data is lost. `save_artist` refuses more
  than 40. Scenario: an artist with more than 40 aliases after several merges can no longer be edited in the dialog
  (rename, add a channel URL), because «Too many aliases» blocks it. Fix: use one limit everywhere, and report the
  overflow during merge instead of truncating.
- **m7 – Temporary file and path limit** (`playlists.py:270`, `:349`). `target_path` allows up to
  `max_path_length - 1` (≤ 258), but `<name>.m3u8.tmp` is 4 characters longer. Without LongPathsEnabled, the write
  fails on Windows with «write failed» when the length is ≥ 257. In addition, an unrelated file with the same `.tmp`
  name is silently overwritten, and a headless and a GUI sync of the same file share the same tmp name. Fix: subtract
  4 in the length check, and use a unique tmp name (`tempfile.mkstemp(dir=...)`).
- **m8 – «& MC …» becomes a b2b partner** (`artists.py:59`, `_WEAK`). `Will Sparks & MC Stretch` →
  `['Will Sparks', 'MC Stretch']` (b2b). The docstring says MC credits are dropped, but that only happens after
  `feat.`. Fix: drop pieces that start with `MC `.
- **m9 – Hidden artists show up as b2b partners** (`artists.py:620`). `detail().with` does not filter hidden artists
  (`names_of` does). Scenario: a mix series that was wrongly recognised and hidden appears as «b2b with …».
- **m10 – Event listener accumulates** (`ui/js/views/settings.js:469`). `HC.bridge.on('playlists_changed', …)` is
  registered each time the storage tab is painted. The `isConnected` check prevents wrong paints, but the listeners
  and their `load()` closures pile up (memory and needless checks). Other views subscribe once in `init`; do the same
  here.

## Nits

- `api.py:2344`, `headless.py:191`: «Playlist sync failed» is hard-coded English in the log, which the UI streams
  live. There is a precedent (`Tracklist not readable`), but `tr()` would be consistent.
- `set_playlist_sync`, `forget_playlist`, `sync_playlists`: `int(...)` on an invalid id raises an exception to JS
  instead of returning `{ok:false}`.
- Relative paths are written with `\`. Car radios and Android players often only accept `/` (the docstring mentions
  USB sticks). An option, or always `/`, would be more portable; Windows players accept both.
- A name such as `foo.m3u8` becomes `foo.m3u8.m3u8`.
- In `djs.js:104` a `span[role=button]` sits inside `button.dj-card`, which nests interactive elements
  (accessibility).

## Nachtrag (integrator, 2026-11-18)

Behoben:

- **M1:** `split_credit` schützt zuerst jede bekannte Schreibweise (Startliste + eigene Artists/Aliasse,
  längster Treffer zuerst) mit Platzhaltern; erst danach werden `feat./ft./featuring/w//hosted by/presents/pres.`
  abgeschnitten und getrennt. `with` schneidet nur noch vor «MC …» ab bzw. trennt zwischen zwei bekannten Namen.
  `_clean_name` schneidet nichts mehr ab. «Mark With a K» ist neu in der Startliste. Tabellentests in
  `tests/test_review8.py` (Mark With a K, Headhunterz presents, Sub Zero Project, Brennan Heart & Wildstylez,
  D-Block & S-te-Fan, Angerfist b2b Miss K8, MC Nolz, Withheld) und ein eigener Artist mit «Presents» im Namen.
- **M2:** Migration 14 – Trigger zählen `state.artists_rev_rows` (videos-Zeile mit Status done in einer vom
  Index gelesenen Spalte, Löschen, bestätigte `checklist_rows`) und `state.artists_rev_names` (`artists`,
  `series`) hoch; die Signatur besteht nur aus diesen beiden Werten und den Festival-Settings. Damit sind
  `set_manual`/`reset_manual`/Zuordnungslauf/Sammler/Retag/Löschen/Merge/Split und Headless-Läufe in einem anderen
  Prozess abgedeckt. Download-Fortschritt bumpt nicht. Test: `test_cache_follows_*`, `test_download_progress_does_not_bump`.
- **m1:** inkrementeller Neuaufbau (nur geänderte Sets neu parsen, Memo im Index), `fx.norm` mit `lru_cache`,
  ein Regex über alle Serien-Aliasse und Bühnennamen einmal pro Katalog. 10 000 Sets: voll ca. 1,3 s (vorher
  3,8 s), nach einem Download ca. 0,07 s.
- **m2 (+ QA-Defekt):** relativer Eintrag, der mit `#` oder Leerraum beginnt, wird als `.\…` geschrieben.
- **m3:** automatischer Sync legt eine gelöschte Datei nicht neu an, schaltet `sync` aus und zählt `gone`;
  ausdrückliches «Jetzt schreiben» (`ids`) schreibt sie.
- **m4:** `_LINE` erfasst auch `\v \f U+0085 U+2028 U+2029`; Fallback-Titel und Pfad werden bereinigt.
- **m5:** `_request_playlist_sync` hängt einen Done-Callback an; ist danach noch etwas offen, folgt ein neuer Job.
- **m6:** ein Limit (`MAX_ALIASES = 80`) für Dialog und Merge; Merge verweigert statt abzuschneiden.
- **m7:** eindeutige Temp-Datei (`mkstemp`, `.hcl-*.tmp`, 0644), deren Länge in `target_path` mitgeprüft wird.
- **m8:** MC neben einem DJ fällt weg, ein MC allein bleibt.
- **m9:** ausgeblendete Artists erscheinen nicht mehr als b2b-Partner.
- **m10:** `playlists_changed` wird einmal in `init` abonniert.
- **Nits:** Sync-Fehler über `tr("playlist.sync_crashed")` (API + Headless); ungültige Ids → `{ok:false}`;
  `foo.m3u8` wird nicht zu `foo.m3u8.m3u8`.
