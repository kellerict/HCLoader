# Review v0.5.1 – WebView2 Runtime (Installer-Bootstrapper, CI-Signaturprüfung, App-Hinweis)

Umfang: `git diff 2a493ba..HEAD` (941a98f). Reviewer: unabhängig, kein Code geändert.
Lokal geprüft: `pytest tests/test_webview2.py tests/test_installer.py tests/test_i18n*.py` grün,
`ruff check app tests` sauber. Installer/CI-Pfade nur statisch geprüft (Linux-Umgebung).

## Ergebnis: ÄNDERUNGEN NÖTIG

Erkennung, Signaturprüfung, i18n und Modulgrenzen sind solide. Zwei Punkte verletzen aber die
ausdrückliche Vorgabe «Installer hängt nie, auch nicht silent» und sollten vor dem Release behoben
werden (beide klein).

## Funde (nach Schwere)

### M1 – Unbegrenzte Wartezeit auf den Bootstrapper
`installer/HCLoader.iss:356` – `Exec(Setup, '/silent /install', …, ewWaitUntilTerminated, …)`
wartet ohne Obergrenze. Der Bootstrapper lädt ~150 MB über EdgeUpdate; hinter einem hängenden
Proxy, Captive Portal oder bei einem blockierten EdgeUpdate-Dienst kann er sehr lange oder gar nicht
zurückkehren. Im ssPostInstall-Schritt gibt es keinen Abbrechen-Knopf; bei `/VERYSILENT` bleibt
der Setup-Prozess einfach stehen. CI deckt das nicht ab (Runner hat die Runtime, Dry-Run startet
nichts).
**Vorschlag:** gebundenes Warten, z.B. `CreateProcessW`/`WaitForSingleObject` per
`external '…@kernel32.dll stdcall'` in einer Schleife (z.B. 500 ms-Takt mit
`WizardForm.Refresh`/ProcessMessages) bis max. ~10 Min.; bei Timeout loggen
(`WebView2 install timed out`), Prozess weiterlaufen lassen und Setup normal beenden (App erklärt
es beim Start). Alternativ `ewNoWait` + Polling von `FindWebView2` mit Deadline.

### M2 – Fehlermeldung blockiert unbeaufsichtigte Installationen
`installer/HCLoader.iss:374` – `SuppressibleMsgBox` wird nur mit `/SUPPRESSMSGBOXES` unterdrückt,
**nicht** durch `/SILENT` oder `/VERYSILENT`. Ein `/VERYSILENT`-Install offline zeigt also eine
modale Box und hängt bis jemand klickt. Der Kommentar `HCLoader.iss:318` («suppressed in silent
mode») und `docs/decisions.md` beschreiben das falsch.
**Vorschlag:** `if not WizardSilent then SuppressibleMsgBox(…)` (Log-Zeile bleibt immer), Kommentar
korrigieren. Optional ein CI-Schritt mit `/WEBVIEW2DRYRUN=1` + simuliertem Fehler (z.B.
`/WEBVIEW2DRYRUN=fail`) ohne `/SUPPRESSMSGBOXES`, gebunden durch `Invoke-Bounded`.

### L1 – Reihenfolge in ssPostInstall
`installer/HCLoader.iss:382-383` – `InstallWebView2()` läuft vor `WriteInstallerDefaults()`. Hängt
oder wird der Bootstrapper-Schritt abgebrochen (Task-Manager, Timeout eines Deployments), fehlt
`installer-defaults.json` und die Datenschutz-Wahl (Update-Prüfung aus) geht verloren.
**Vorschlag:** zuerst `WriteInstallerDefaults()`, dann `InstallWebView2()`.

### L2 – App-Prüfung und pywebview sehen nicht exakt dieselben Schlüssel
`app/core/webview2.py:40` prüft auf 64-bit zusätzlich `HKLM\SOFTWARE\Microsoft\EdgeUpdate\…`
(64-bit-Sicht); pywebview (`platforms/winforms.py _is_chromium`) liest auf x64/ARM64 nur
`WOW6432Node` + HKCU und verlangt zusätzlich `pv >= 86.0.622.0` und .NET >= 4.6.2. Ein Treffer nur
in der 64-bit-Sicht oder ein uraltes `pv` ergäbe «vorhanden» in der App, aber MSHTML-Fallback in
pywebview. In der Praxis sehr selten (Microsoft schreibt per-machine nur nach WOW6432Node).
**Vorschlag:** optional Mindestversion 86.0.622.0 in `is_valid_version` übernehmen; den
64-bit-HKLM-Pfad nur als zusätzlichen Treffer loggen. Kein Blocker.

### L3 – Installer ignoriert Preview-Kanäle
`installer/HCLoader.iss:306-313` – nur der Stable-Client-Key; ist nur Beta/Dev/Canary installiert,
installiert Setup zusätzlich Stable. Harmlos (keine kaputte App, nur ein unnötiger Download);
bewusst so lassen oder im Kommentar erwähnen.

### L4 – Signaturprüfung: Signer nur über Subject-Regex
`.github/workflows/portable.yml:115-116` – `Status -eq 'Valid'` erzwingt eine vertrauenswürdige
Kette, und `O=Microsoft Corporation` ist bei öffentlichen CAs nicht frei erhältlich – daher
ausreichend. Härter wäre zusätzlich: Issuer `CN=Microsoft Code Signing PCA*` bzw. Root
`Microsoft Root Certificate Authority 2010/2011` (via `X509Chain`) prüfen. `-MaximumRedirection 10`
erlaubt theoretisch einen http-Hop; durch die Signaturprüfung neutralisiert. Bounded: 2 Versuche,
`-TimeoutSec 120`, `timeout-minutes: 5` – ok.

### Info (geprüft, in Ordnung)
- Erkennung entspricht der Microsoft-Doku («Detect if a WebView2 Runtime is already installed»):
  `pv` (REG_SZ) unter `…\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`, per machine
  `HKLM32` (= WOW6432Node, Installer ist `x64compatible`-only), per user HKCU; leer/`0.0.0.0` =
  fehlt. Kein falsches «fehlt» durch fehlende Schlüssel-Sichten.
- Bootstrapper-Schalter `/silent /install` wie dokumentiert; nicht elevated (`PrivilegesRequired=lowest`)
  → per-user Installation ohne UAC, wie von Microsoft beschrieben.
- Fehler (Extraktion, Exec, Exitcode ≠ 0) brechen Setup nie ab; Exit 0 ohne `pv` wird nur geloggt.
- `/WEBVIEW2DRYRUN=1` testet Extraktion ohne Start; CI prüft Log-Zeilen für «present» und Dry-Run.
- Bootstrapper nicht im Git (`/installer/redist/` in `.gitignore`), `dontcopy`, nie nach `{app}`;
  ISCC bricht ab, wenn er fehlt. Keine Secrets, keine User-Pfade.
- App: Prüfung nur im GUI-Pfad, nur Windows, Fehler der Prüfung blockieren nie, Escape-Hatch
  `HCLOADER_SKIP_WEBVIEW2_CHECK`; MessageBox respektiert `HCLOADER_NO_DIALOG`.
- i18n: `main.webview2_missing`/`main.open_page` in allen 18 Katalogen (nl-BE via Fallback),
  übersetzt, de ohne «ß»; Installer-Texte in allen 10 Installer-Sprachen (`.isi`, UTF-8 BOM).
- Modulgrenzen: `core/webview2.py` ohne UI-Bezug, nur Registry, kein Netzwerk; kein yt-dlp-Bezug;
  YouTube-Throttle nicht berührt.
