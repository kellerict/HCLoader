## Findings

### Minor

1. **`ui/js/views/watchlist.js:103–111, 488–489` – row menu outlives its row.** `rowMenu` anchors to the row's `⋯` button. If the table re-renders while the menu is open (check/backfill progress events, `refresh()`), the anchor is detached: the menu stays at the old position, acts on the captured `s` object, and on Escape/Tab `ui.closeMenu` cannot return focus (`_anchor.isConnected` false) so focus drops to `<body>`. Suggestion: close the menu in `render()`/`refresh()` when `ui._menu?._anchor` is inside `#wl-body`, or re-resolve the anchor by `data-id` after re-render.

2. **`ui/js/components.js:97–131` – menus don't toggle.** The race fix (`sysWasOpen`, `ui/js/app.js:150,187`) makes only the status-bar popover close on a second click of its button. All `ui.menu` users (watchlist `⋯`, library `⋯`, DJ page `⋯`, genre menu) still close on mousedown and reopen on click. Suggestion: move the «was this anchor's menu open on mousedown» logic into `ui.menu`/`arm` (compare `e.target` with `ui._menu._anchor`) so every anchor behaves alike, and drop the app.js special case.

3. **`ui/js/app.js:150` – stale `sysWasOpen`.** It is only reset by the next click on `#sb-sys`. A mousedown on the button followed by a drag-off (no click) leaves it `true`; the next keyboard activation (Enter/Space, no mousedown) of the button then returns early and does nothing. Suggestion: reset it in a `click` capture or at the end of every mousedown cycle (e.g. `setTimeout(() => sysWasOpen = false)`), or solve via finding 2.

4. **`ui/js/components.js:160–170` – popover focus management.** `ui.popover` does not set `el._anchor`, so the System popover (`role=dialog`) neither moves focus into itself nor returns it to `#sb-sys` on Escape. Harmless today (content is read-only), but `aria-haspopup="dialog"` promises a dialog. Suggestion: set `el._anchor = anchor` in `ui.popover` so `closeMenu` restores focus; optionally `tabindex="-1"` + focus when opened by keyboard.

5. **`ui/js/components.js:104`, `:126` – menu a11y details.** `role="menu"` now contains `div.mhead` without a role (should be `role="presentation"` or a `role="group"` with `aria-labelledby`); arrow keys only work once focus is inside the menu, so a mouse-opened menu ignores arrows. Suggestion: give `.mhead` `role="presentation"`; on ArrowDown in the anchor while the menu is open, focus the first item.

6. **`ui/js/views/settings.js:1385` – group headers inside `role="tablist"`.** `div.stab-group role="presentation"` with text is tolerated, but the group names are not announced as grouping for the tabs. Acceptable; nicer: `aria-describedby`/`aria-label` per tab or `role="group"` wrappers outside the tablist semantics.

7. **`ui/css/components.css:604` – dead rule.** `#nf-next{white-space:nowrap}` targets the removed nav-foot element. Delete. (Check `.nav-foot` at `:28` too – it now only holds the mock flag.)

8. **`ui/js/views/discover.js:431` – keyword group starts collapsed.** Active include/exclude keywords from the settings are now hidden behind `<details>`; the summary count mitigates it. Consider `open` when `f.inc.length || f.exc.length` differs from the saved defaults, so session-only changes stay visible.
