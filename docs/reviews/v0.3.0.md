## Major

### M1 – Flat results re-run detection on library items and wipe assignments that came from the description
`app/core/discover.py:211`, `app/core/watchlist.py:539/547`, `app/core/series.py:300-353`

`store_results` passes **every** hit id (including rows with status `done`) to
`detect_and_store`. `check_source` does the same for existing rows (`touched.append(vid)` at 539).
Flat listings almost never deliver a description, but the detection after download
(`ytclient.py:1082`) and the «Assign festivals» pass (sidecar) do use the full
description. `apply_detection` then overwrites the stored non-manual result with the weaker one
(or with nothing).

Reproduced:
```
title = "Headhunterz | Closing Ceremony 2024 | RED"   status done
detect_and_store(..., descriptions={"abc": "Live at Defqon.1 Weekend Festival 2024"})  -> edition 1
discover.store_results(db, [{"id": "abc", "title": title}], ...)                    -> edition None
```
Result: the mix drops out of its festival in the library just because it showed up in a search
or watchlist check. The file still carries `TXXX:FESTIVAL`/album = edition, so DB and tags
diverge, and the next pass flips it back. Same pattern for the year: a flat result with
missing/approximate `upload_date` can move an item to another edition (`year_from_upload_date`).

Suggestion: in `detect_and_store` from flat sources, skip rows whose status is in
`_GENRE_LOCKED` (queued/downloading/done) – their detection belongs to the download step and
the explicit pass – or at least never replace an existing assignment with a weaker/empty result
when no description was supplied. Add a regression test (search hit of a `done` row with an
assignment from the description must keep it).

## Minor

### m1 – Toggling «enabled» (or saving unchanged) marks a built-in as `user_modified`
`app/core/series.py:680-681`, `ui/js/views/settings.js:906-910`
The toggle sends the whole series to `save_series`; `modified` compares the stored JSON with the
re-validated `_clean_strings` output. `_clean_strings` drops case-insensitive duplicates, so for
`rebirth` (`aliases: [Rebirth Festival, REBiRTH Festival]`, `app/data/series.yaml:81`) the
comparison differs and the series is frozen against future `series.yaml` updates (and gets a
«reset» button) just by switching it off. Verified with a script for all 35 built-ins: only
`rebirth` is affected today, but any future YAML entry with such duplicates or >80-char aliases
behaves the same. Suggestion: separate `set_series_enabled(id, bool)` path, and/or compare
normalised values; fix the YAML duplicate.

### m2 – Race: pass vs. delete/hide of a series
`app/core/series.py:398-419`, `706-718`
`assign_pass` uses a catalog snapshot. Deleting a user series during the pass makes
`ensure_edition` insert an edition for a now missing `series_id` -> FK `IntegrityError` ->
whole pass ends with «pass failed». Hiding a built-in during the pass lets the rest of the pass
re-create assignments to the hidden series. Suggestion: refuse `delete_series`/`save_series`
while `festivals` job runs, or catch FK errors per row and re-check `hidden`.

### m3 – Built-in dropped from series.yaml while hidden becomes an unrecoverable zombie
`app/core/series.py:143-146`, `721-731`
A hidden built-in that disappears from the file gets `builtin=0, hidden=1`. «Show hidden» lists it
with «Restore», but `reset_series` answers `not_builtin`. Conversely a key that comes back into the
file later stays `builtin=0` and never receives updates. Suggestion: on drop also set `hidden=0`
(or delete if no assignments); on re-appearance re-adopt rows with matching key that are not
`user_modified`.

### m4 – Alias clash check ignores hidden series and built-in syncs
`app/core/series.py:627`, `105-150`
A user can create an alias that a hidden built-in owns; `reset_series` or a new `series.yaml`
entry can then introduce duplicate aliases without any validation. Detection stays deterministic
(first by id wins on equal rank), but silently. Suggestion: warn in `reset_series`/sync (log) or
include hidden rows in the check.

### m5 – Pass writes one autocommit per changed row
`app/core/series.py:346-352`
Measured 10'000 rows: 4.8 s first pass, 1.9 s re-run (Linux). On Windows with WAL +
`synchronous=FULL` each commit is an fsync; large libraries on HDD/NAS will be noticeably slower.
Suggestion: commit in batches of ~200 rows (short transactions, lock released between batches so
downloads are not blocked). Also `K_LAST_PASS` is set when the pass is cancelled (line 423) –
the status then shows a completed-looking date.

### m6 – `delete_series` clears manual assignments, files keep old tags
`app/core/series.py:693-703`
Documented in the docstring and the delete dialog («n mixes lose their assignment»), acceptable.
But the affected rows switch back to automatic (`festival_manual=0`) and their files keep
`TXXX:FESTIVAL`/album until a retag. Suggestion: mention «retag to update files» in the dialog
warning or offer it.

### m7 – Single-segment edge in path tidy
`app/core/paths.py:181-196`
If an optional placeholder is the only content of the **file** segment (e.g. template
`{genre}/{id}/{stage}`), an empty value renders `_.mp3` for every item in that folder level.
Exotic (validator only requires `{id}` somewhere). Suggestion: require `{id}` or `{title}` in the
last segment, or fall back to `{id}` when the last segment tidies to empty.

## Checked and fine

- **Migration 7** (`app/core/db.py:175-231`): only `conn.execute`, runs inside the existing
  `BEGIN … COMMIT` per step with rollback; version-gated (idempotent); pre-migration backup via
  `before()` (test `hcloader-premigrate-v6-to-v7-*`); older app gets `SchemaTooNewError` with the
  backup hint. FKs `ON DELETE SET NULL/CASCADE` effective (`PRAGMA foreign_keys=ON`). Indexes
  present.
- **Manual flag**: every automatic write is guarded with `AND festival_manual=0`; `set_manual`
  validates ids, year range, set type, episode; `reset_manual` re-detects offline.
- **Built-in merge**: hash-gated sync, `user_modified`/`hidden` respected, `u-` keys never
  collide with built-ins, sync under lock and in one transaction.
- **SQL**: all values parameterised; f-strings only interpolate constant column lists, `?`
  marks and whitelisted expressions (`group_counts` raises on unknown `by`, API maps to error).
- **XSS**: every new `innerHTML` site in `ui/js/festivals.js`, `views/library.js`,
  `views/settings.js` escapes series names, aliases (chips), variants, stages, titles, error
  texts; `ui.confirm`/`ui.toast`/modal title escape; stage colours come from a fixed map; numeric
  ids/counts only.
- **Worker/UI thread**: the pass runs in the maintenance worker, mutually exclusive with other
  maintenance jobs, cancel checked per row and set on shutdown, progress every 25 rows plus
  final event; bridge methods are cheap reads.
- **Tagging**: album = edition only when `storage.album_from_edition` and an edition exists;
  festival TXXX frames are in `_OWN_FRAMES` (removed on retag when gone), foreign frames kept;
  MP4/Opus remove stale keys. Retag uses the stored assignment, no re-detection.
- **Paths**: optional placeholders sanitised, `0` year dropped, empty folder levels removed,
  shortened with the other fields in the Windows length loop; queue target honours them.
- **Boundaries**: `yt_dlp` only in `ytclient.py`; `series.py`/`festivals.py` have no network,
  no GUI imports; `throttle.py` untouched; detection uses only stored flat data.
- **i18n / configurability**: all `tr()` keys used in the new backend code exist in `en` and `de`;
  no `ß` added to the de catalogs; all `festivals.*` settings and `storage.album_from_edition`
  are reachable in the GUI; no hard-coded UI strings found in the new views.
- **Hygiene**: no binaries, DBs, cookies or user paths added.

## Nachtrag (2026-11-17, integrator)

Behoben:
- **M1:** `detect_and_store(..., flat=True)` aus `discover.store_results` und `watchlist.check_source`:
  queued/downloading/done werden übersprungen, bestehende Zuordnungen/Vorschläge nie durch schwächere
  oder leere Ergebnisse ersetzt (`apply_detection(keep_stronger=True)`). Regressionstests für Suche und
  Watchlist (done/queued/downloading) sowie für neue Einträge.
- **m1:** neue Bridge-Methode `set_series_enabled(id, enabled)` (Toggle in den Einstellungen, Mock,
  `bridge.js`, `docs/bridge-api.md`); `save_series` vergleicht normalisierte Inhalte; Duplikat bei
  `rebirth` in `series.yaml` entfernt.
- **m2:** `apply_detection` prüft, ob die Serie noch existiert und sichtbar ist (sonst «keine
  Erkennung»); der Durchlauf lädt den Katalog pro Block neu. Kein Abbruch, keine Neuzuordnung.
- **m3:** beim Wegfall aus `series.yaml` wird `hidden=0` gesetzt; kehrt der Schlüssel zurück, wird eine
  nicht vom User geänderte Zeile wieder mitgeliefert (`builtin=1`).
- **m4:** `reset_series` loggt Alias-Konflikte mit anderen sichtbaren Serien (Warnung).
- **m5:** Durchlauf in Transaktionen à 200 Zeilen (Erkennung/Sidecar ausserhalb des Locks);
  `K_LAST_PASS` nur bei vollständigem Durchlauf.
- **m7:** leeres Dateinamen-Segment fällt auf `{id}` zurück.

Akzeptiert:
- **m6:** im Dialog und Docstring dokumentiert; ein Hinweis «neu taggen» bräuchte neue Texte in allen
  Sprachkatalogen – für eine spätere Phase vorgemerkt.
- **m4 (Rest):** Prüfung beim automatischen Sync nur über die Warnung bei `reset_series`; Erkennung
  bleibt deterministisch.
