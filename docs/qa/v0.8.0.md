## 1. M3U8 - Bestanden (mit Mangel M1)
Eigener Parser (`scratchpad/qa/m3u.py`): prueft kein BOM, UTF-8, `\n` ohne `\r`, Zeile 1 = `#EXTM3U`, jede Pfadzeile hat
vorangehendes `#EXTINF:<sek>,<Text>`, und dass jeder Pfad (relativ zum Playlist-Ordner aufgeloest) auf eine echte Datei zeigt.
- Format: `#EXTINF:3601,Angerfist - Defqon.1 2024 | BLACK`, Dauer in Sekunden, "Artist - Titel". OK.
- Relative Pfade mit Unterordnern, Leerzeichen, Umlauten/Sonderzeichen (`Ünïcode Säť #1 [live].mp3`, `日本語 set.mp3`,
  `set 100% (a&b).mp3`, `#` im Namen): Playlist in `Playlists/` -> `../Hard Core/Sub Dir/...`; Playlist im Musik-Root ->
  `Hard Core/Sub Dir/...`; Playlist ausserhalb -> `../../My Music/...`; absolut -> volle Pfade. Alle aufloesbar. OK.
- Absoluter Fallback ueber Windows-Laufwerke (Simulation `entry_path(..., ntpath)`): `C:\Music\Hard\a #1.mp3` ab
  `C:\Music\Playlists` -> `..\Hard\a #1.mp3`; `D:\Music\a.mp3` -> absolut, fallback=True; `\\nas\share\a.mp3` -> absolut, fallback=True;
  Gross-/Kleinschreibung des Laufwerks egal. `absolute_fallback` wird gezaehlt (Test `test_render_counts_absolute_fallback_on_windows`).
- Dateiname: `Test: a/b?*` -> `Test- a-b.m3u8`; `CON`/`NUL` -> `_CON.m3u8`/`_NUL.m3u8`; `a.` -> `a.m3u8`; nur Leerzeichen -> Fehler
  "Please enter a file name"; 200 x `X` bei max_path_length 120/260 -> gekuerzt auf 119/142 Zeichen (< Limit, `windows_length`);
  Ordner schon zu lang -> klare Fehlermeldung statt Absturz.
- Ueberschreiben: zweiter Export ohne `overwrite` -> `{ok: False, exists: True, path}`; UI-Dialog fragt im Dialog ("Overwrite"/"Ueberschreiben"), Screenshot `de-export-exists.png`.
- Sync nach Downloads (Setting `playlists.sync_after_download`): GUI-Pfad `_after_download` -> eigener Playlist-Thread
  (Test `test_api_playlists_and_sync_after_download`, gruen, inkl. Event `playlists_synced`). **Headless**: eigener Test
  (`scratchpad/qa/test_hl.py`) mit FakeQueue, die waehrend `run_pending` ein Set hinzufuegt: Setting an -> gespeicherte Playlist
  (sync=1) hat danach 2 Eintraege, Setting aus -> 1 Eintrag. OK.
- Fehlende Dateien werden uebersprungen (`skipped`), Schreiben atomar (`.tmp` + `os.replace`).

**M1 (mittel): relativer Pfad, der mit `#` beginnt, wird in jedem M3U-Parser zum Kommentar.** Liegt die Playlist im Musik-Root und
heisst ein Unterordner `#Hash Folder`, schreibt der Export `#Hash Folder/set 100% (a&b).mp3`; mein Parser (und jeder Player) liest das
als Kommentarzeile, der Eintrag verschwindet (Zaehler sagt 3, Parser findet 2). Betrifft nur relative Pfade, die direkt mit `#`
beginnen (Playlist im selben Ordner/Elternordner, Standardordner `Playlists/` ist nicht betroffen wegen `../`). Vorschlag: `./`
voranstellen, wenn der Pfad mit `#` beginnt. Reproduktion: `scratchpad/qa/m3u.py` (zweiter Lauf).
